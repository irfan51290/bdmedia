The Problem

When you're solo-building, you're flying blind after launch. You don't know which pages are throwing errors, you don't know what users actually think, and by the time you find out a feature is broken it's been broken for days. Most error monitoring tools are built for teams with budgets — not indie builders shipping one app a week. And feedback tools are completely separate from error tools, forcing you to context-switch between dashboards just to understand what's happening in your own product.

How It Works

  • Install the SDK with one command — wraps your React app in an error boundary and adds a floating feedback widget
  • Every unhandled error is caught, logged to Supabase with the page URL, stack trace, and occurrence count
  • Users can submit feedback directly from the widget — Claude AI categorises it by sentiment, theme, and priority
  • A Telegram notification fires when errors spike or feedback comes in, so you know immediately
  • The dashboard shows all your projects in one place — errors by severity, feedback queue with one-click approve/archive, and GitHub issue creation
  • Weekly digest email summarises what broke and what users said, so you always stay on top of it

What I Learned

Building a reusable SDK is a completely different challenge from building a product. You're writing code that runs inside someone else's app — you can't control the environment, the React version, or how they've set up their CSS. On Windows with Turbopack, even the standard npm install file: symlink approach breaks, which forced me to use npm pack + tarball installs. The multi-tenant dashboard architecture was also a first — each project has its own Supabase connection, resolved at runtime from environment variables, so the same dashboard codebase can serve any number of apps without redeployment.

Built With Claude

Claude designed the full SDK architecture — the React error boundary wrapper, the feedback widget component, and the API routes for logging errors and feedback. The trickiest design decision was making the SDK work with both Pages Router and App Router projects without forcing a 'use client' boundary too high in the tree. Claude also designed the multi-project Supabase schema, the Claude AI categorisation pipeline for feedback, and the dashboard UI system — iterating through five design variants before landing on the clean light design shown above.
