The Problem

Most developer portfolios are static — a list of projects, a bio, maybe a GitHub link. They don't reflect how someone actually builds or thinks. I wanted a portfolio that was itself a project: something living, evolving, and worth revisiting each week.

How It Works

  • A single projects.js file is the source of truth — add a project once, it appears everywhere
  • Each project gets a full detail page with mockup, problem statement, and skills breakdown
  • Visitors vote on which projects they want developed further — stored in Supabase with realtime updates
  • A live leaderboard ranks all projects by community votes
  • Floating hero cards link directly to their project in the journey timeline
  • No framework, no build step — pure HTML, CSS, and vanilla JS

What I Learned

Designing for your own work is surprisingly hard — every decision about layout, copy, and hierarchy is also a statement about what you value. I learned more about visual design and UX writing building this than any tutorial could have taught me. The constraint of zero frameworks also forced cleaner, more intentional code.

Built With Claude

Every pixel of this site was built in conversation with Claude Code. The design system, the Supabase realtime voting layer, the leaderboard, the floating hero cards — all of it was shipped in a week through iterative back-and-forth. The portfolio itself is proof that the "1 app, 1 week" format works.
